# 网盘账号控制台与会话保活

## 概述

本规格描述网盘账号的会话保活、空间信息刷新，以及网盘账号控制台的导航、详情、文件浏览与账号新增/编辑行为。目标是让账号在平台会话过期前自动续期、不再出现「登录一会就掉线」，并把控制台从「列表 + 独立文件页」改为「平台一级菜单 + 账号详情内嵌文件浏览」。保活采用与 YunX-Desktop 一致的思路：不依赖定时心跳，而是在每次使用凭据前按时间窗惰性续期，并把服务端下发的新会话 Cookie 立即回写。

## 凭据保活

夸克与 UC 的会话 Cookie（`__puus`/`__pus`）有效期约 3 小时。取凭据的出口统一经过续期判断：距上次刷新超过 90 分钟才真正刷新，未超过直接返回当前凭据；刷新成功后写回数据库并更新时间戳，刷新失败时回退到旧凭据，不中断业务、不清空账号。任意 API 响应携带新的会话 Cookie 时，必须与请求所用的凭据合并后回写，并按「本次请求使用的凭据」定位账号行，多账号场景不得写入其他账号。鉴权类失败（401 或平台失效码）先刷新一次并重试原请求，只重试一次；网络错误、超时和限流不触发刷新、不改账号状态。

## 令牌型平台续期

光鸭与迅雷使用 `refresh_token` 续期。光鸭登录时已保存 `refresh_token` 与 `expires_at`，在 access_token 临期（到期前 60 秒）或未知时用 refresh_token 换取新 token，并把新 token 与新的过期时间写回；refresh_token 返回为空时保留旧值，不得覆盖。迅雷网页登录必须同时保存 `refresh_token` 与 `expires_in`；请求前本地解析 JWT 的 `exp`，剩余不足 60 秒时先续期；响应为 401 或 `unauthenticated` 时续期并重试一次，续期后需要重建 captcha 再发请求。两家续期失败都保留旧凭据，并返回可读的「登录已过期，请重新登录」提示。115、123、139 与百度没有续期接口，不做伪刷新，只在鉴权失效时标记 `expired` 并提示重新登录。

## 账号状态与启动刷新

账号状态为 `active`、`expired` 或 `unknown`。探测返回 `unknown` 时不得覆盖已有的 `active`；网络抖动导致的 `unknown` 不发送告警。重新登录、编辑凭据或重新授权成功后，账号状态恢复为 `active`，并重新进入自动选号池。进程启动后立即执行一次账号刷新与探测，不再等待 6 小时的首次调度；之后的周期探测保持 6 小时。

## 空间信息定时刷新

定时任务每 30 分钟遍历全部网盘账号，调用平台空间接口并把已用、总空间写回账号记录。任务不修改最近检测时间、不修改账号状态、不清空凭据；单个账号失败只记录一条告警并继续处理其余账号；同一账号连续失败不重复刷屏告警。任务在调度目录中声明为可手动触发，并在启动后按周期首次执行。

## 迅雷用户名

迅雷账号的昵称来源包括：登录时写入的凭据字段、`drive/v1/about` 返回的用户信息。用户信息可能位于响应顶层，也可能位于 `data` 或 `data.user` 等嵌套对象中，解析时必须覆盖这些结构，并按 `nickname`、`nick_name`、`nickName`、`user_name`、`userName`、`name` 依次匹配。新增账号、手动检测与定时刷新都应写回昵称；解析不到昵称时保留数据库中已有昵称，不得写成空串覆盖。

## 控制台导航

网盘账号控制台左侧以网盘平台为一级菜单。每个平台菜单项展示平台图标与中文名称，首次进入时全部展开，直接显示该平台下的账号列表；用户点击平台标题可以折叠或重新展开，展开状态可同时存在多个平台。账号条目展示状态、名称（优先平台昵称，其次用户命名）、主账号标记与空间占用进度。移动端使用相同分组，平台标题显示中文名与图标，默认同样全部展开并可折叠。

## 账号详情

选中账号后，详情顶部为标签行与左右两栏。标签行左侧展示平台标签、状态标签与主账号标签；标签行右侧依次放置操作按钮：检测连通性、刷新令牌、设为主账号、编辑账号、删除账号，窄屏时整体换行。左右两栏中左侧账号信息约占 70%，右侧存储空间约占 30%。账号信息展示账号名称、平台昵称（存在时）、最近检测时间与已保存凭据；不展示过期时间。已保存凭证以单行只读输入框展示，内容不换行、不撑高页面，输入框尾部提供复制按钮；凭据明文只通过超级管理员鉴权的详情接口获取，列表接口继续返回脱敏结果。存储空间展示进度条、已用、总量与剩余空间，超过 80% 与 95% 分别使用警告色与错误色。

## 文件信息

账号信息与存储空间下方内嵌文件浏览面板：展示当前目录的文件与文件夹列表（名称、大小、修改时间），支持进入子目录与返回上级，支持对文件执行分享、移动、重命名与删除。文件列表为空、账号不支持文件操作或接口失败时，面板给出对应提示且不影响账号信息与存储空间展示。系统设置中的「网盘文件」tab、独立 `/netdisk` 页面与其路由一并移除。

## 账号新增与编辑

新增与编辑使用同一组字段：平台、名称、是否主账号，以及登录方式区域。登录方式区域包含四种方式：粘贴 Cookie、CookieCloud 导入、账号密码（平台支持时，含短信验证码切换）、网页登录扫码。该区域必须作为对话框正文的正常子节点渲染，任何包裹层都不得使内容在浏览器中不可见。编辑时平台锁定不可更改，其余字段与新增一致：可以直接替换 Cookie，也可以通过 CookieCloud、账号密码、短信或网页登录对已有账号重新授权；重新授权成功后写回新凭据并把状态置为 `active`。保存名称后，列表与详情立即显示新名称。后端编辑接口按平台解析凭据文本：123 与光鸭的裸 JWT 识别为 token 凭据，其余平台识别为 Cookie。

## 平台显示名

平台的中文名称与图标由单一来源提供，覆盖控制台的平台分组、账号详情平台标签、新增账号的平台下拉与对话框副标题、移动端分组。界面不得出现 `quark`、`pan139` 等内部平台 id。未识别的平台回退为原始 id 并显示通用图标。

## 网页登录弹窗

网页登录弹窗的高度随内容自适应，不预留固定高度。整页截图方式下，二维码或整页画面按容器宽度等比缩放，不因网页自身留白产生上下大块空白；noVNC 方式下画面区域占满可用宽度并保持比例。底部状态区（倒计时与等待提示）紧贴内容。弹窗在移动端全屏展示。

## 登录成功文案

检测到登录态后，弹窗底部显示「当前登录用户：<昵称或账号名>」。用户名优先取后端返回的账号昵称，其次取扫码结果中的账号标识；两者都为空时显示「当前登录用户：未知」。

## 凭据读取与兼容

账号列表接口保持脱敏，只返回凭据字段名与掩码；完整 Cookie 仅由超级管理员鉴权的单账号详情接口返回，前端只在账号详情与编辑弹窗中展示。Cookie/token 明文不得出现在日志、告警、错误信息与测试快照中。历史账号记录（含旧平台 id 与旧凭据格式）继续可读、可编辑、可探测；网盘分享搜索、转存、下载与失败对账行为不变。
