# 网盘账号控制台与会话保活

## 概述

本规格描述网盘账号的会话保活、空间信息刷新，以及网盘账号控制台的导航、详情、文件浏览与账号新增/编辑行为。目标是让账号在平台会话过期前自动续期、不再出现「登录一会就掉线」，并把控制台从「列表 + 独立文件页」改为「平台一级菜单 + 账号详情内嵌文件浏览」。保活采用与 YunX-Desktop 一致的思路：不依赖定时心跳，而是在每次使用凭据前按时间窗惰性续期，并把服务端下发的新会话 Cookie 立即回写。

## 凭据保活

夸克与 UC 的会话 Cookie（`__puus`/`__pus`）有效期约 3 小时。取凭据的出口统一经过续期判断：距上次刷新超过 90 分钟才真正刷新，未超过直接返回当前凭据；刷新成功后写回数据库并更新时间戳，刷新失败时回退到旧凭据，不中断业务、不清空账号。任意 API 响应携带新的会话 Cookie 时，必须与请求所用的凭据合并后回写，并按「本次请求使用的凭据」定位账号行，多账号场景不得写入其他账号。鉴权类失败（401 或平台失效码）先刷新一次并重试原请求，只重试一次；网络错误、超时和限流不触发刷新、不改账号状态。

Scenario: 夸克账号距上次刷新超过 90 分钟时，取凭据会先续期并写回数据库
验收：A1

Scenario: API 响应带回新 Cookie 时合并回写，且多账号场景按请求凭据定位账号不串号
验收：A1

Scenario: 鉴权失败刷新后只重试一次，网络错误与超时不刷新也不清空凭据
验收：A1

## 令牌型平台续期

光鸭与迅雷使用 `refresh_token` 续期。光鸭登录时已保存 `refresh_token` 与 `expires_at`，在 access_token 临期（到期前 60 秒）或未知时用 refresh_token 换取新 token，并把新 token 与新的过期时间写回；refresh_token 返回为空时保留旧值，不得覆盖。迅雷网页登录必须同时保存 `refresh_token` 与 `expires_in`；请求前本地解析 JWT 的 `exp`，剩余不足 60 秒时先续期；响应为 401 或 `unauthenticated` 时续期并重试一次，续期后需要重建 captcha 再发请求。两家续期失败都保留旧凭据，并返回可读的「登录已过期，请重新登录」提示。115、123、139 与百度没有续期接口，不做伪刷新，只在鉴权失效时标记 `expired` 并提示重新登录。

Scenario: 光鸭 access_token 临期时用 refresh_token 续期并写回新 token 与过期时间
验收：A2

Scenario: 迅雷 JWT 剩余不足 60 秒或响应 401 时续期并重试一次
验收：A2

Scenario: 续期失败保留旧凭据并给出重新登录提示，不把账号清空
验收：A2

## 账号状态与启动刷新

账号状态为 `active`、`expired` 或 `unknown`。探测返回 `unknown` 时不得覆盖已有的 `active`；网络抖动导致的 `unknown` 不发送告警。重新登录、编辑凭据或重新授权成功后，账号状态恢复为 `active`，并重新进入自动选号池。进程启动后立即执行一次账号刷新与探测，不再等待 6 小时的首次调度；之后的周期探测保持 6 小时。

Scenario: 探测返回 unknown 时不会把 active 账号降级
验收：A3

Scenario: 重新登录或编辑凭据成功后账号恢复 active 并重新参与选号
验收：A3

Scenario: 进程启动后立即执行一次账号刷新与探测
验收：A3

## 空间信息定时刷新

新增定时任务，每 30 分钟遍历全部网盘账号，调用平台空间接口并把已用、总空间写回账号记录。任务不修改最近检测时间、不修改账号状态、不清空凭据；单个账号失败只记录一条告警并继续处理其余账号；同一账号连续失败不重复刷屏告警。任务在调度目录中声明为可手动触发，并在启动后按周期首次执行。

Scenario: 每 30 分钟刷新全部账号空间并写回已用与总空间
验收：A4

Scenario: 单个账号空间刷新失败时其他账号继续，且账号状态与凭据不变
验收：A4

## 迅雷用户名

迅雷账号的昵称来源包括：登录时写入的凭据字段、`drive/v1/about` 返回的用户信息。用户信息可能位于响应顶层，也可能位于 `data` 或 `data.user` 等嵌套对象中，解析时必须覆盖这些结构，并按 `nickname`、`nick_name`、`nickName`、`user_name`、`userName`、`name` 依次匹配。新增账号、手动检测与定时刷新都应写回昵称；解析不到昵称时保留数据库中已有昵称，不得写成空串覆盖。

Scenario: 迅雷账号能从 about 接口的嵌套用户信息解析出昵称并写入
验收：A5

Scenario: 昵称解析失败时保留已有昵称而不是清空
验收：A5

## 控制台导航

网盘账号控制台左侧以网盘平台为一级菜单。每个平台菜单项展示平台图标与中文名称，默认全部折叠；点击后展开该平台下的账号列表，展开状态可同时存在多个平台。账号条目展示状态、名称（优先平台昵称，其次用户命名）、主账号标记与空间占用进度。移动端使用相同分组，平台标题显示中文名与图标，并支持折叠。

Scenario: 控制台左侧平台默认全部折叠，展开后显示该平台账号
验收：A6

Scenario: 移动端按平台分组显示中文名与图标并可折叠
验收：A6

## 账号详情

选中账号后，详情顶部为左右两栏：左侧账号信息约占 70%，右侧存储空间约占 30%。账号信息展示账号名称、平台昵称（存在时）、最近检测时间与已保存凭据；不展示过期时间。已保存凭据中的 Cookie 默认完整明文展示，并提供复制按钮；凭据明文只通过超级管理员鉴权的详情接口获取，列表接口继续返回脱敏结果。存储空间展示进度条、已用、总量与剩余空间，超过 80% 与 95% 分别使用警告色与错误色。

详情操作行依次为：编辑账号、检测连通性、刷新令牌、设置主账号；删除账号位于编辑账号右侧。不再提供「浏览文件」按钮。设置主账号仅在账号不是主账号时可用；刷新令牌仅在平台支持刷新时出现；删除账号需要二次确认。

Scenario: 详情顶部账号信息与存储空间按 70/30 左右并排，账号信息不含过期时间
验收：A7

Scenario: Cookie 在详情中默认完整明文展示并可复制
验收：A7

Scenario: 检测连通性、刷新令牌、设置主账号与编辑账号同行，删除账号位于编辑账号右侧，且没有浏览文件按钮
验收：A8

## 文件信息

账号信息与存储空间下方内嵌文件浏览面板：展示当前目录的文件与文件夹列表（名称、大小、修改时间），支持进入子目录与返回上级，支持对文件执行分享、移动、重命名与删除。文件列表为空、账号不支持文件操作或接口失败时，面板给出对应提示且不影响账号信息与存储空间展示。系统设置中的「网盘文件」tab、独立 `/netdisk` 页面与其路由一并移除。

Scenario: 账号详情内嵌文件列表并可进入子目录与返回上级
验收：A9

Scenario: 内嵌文件面板保留分享、移动、重命名与删除操作

## 账号新增与编辑

新增与编辑使用同一组字段：平台、名称、是否主账号，以及四种登录方式（粘贴 Cookie、CookieCloud 导入、账号密码/短信、网页登录扫码）。编辑时平台锁定不可更改，其余字段与新增一致：可以直接替换 Cookie，也可以通过 CookieCloud、账号密码、短信或网页登录对已有账号重新授权；重新授权成功后写回新凭据并把状态置为 `active`。保存名称后，列表与详情立即显示新名称。后端编辑接口按平台解析凭据文本：123 与光鸭的裸 JWT 识别为 token 凭据，其余平台识别为 Cookie，避免出现「凭据缺少必填字段」的误报。

Scenario: 编辑账号可切换任一登录方式并保存成功
验收：A10

Scenario: 编辑保存后账号名称在列表与详情立即更新
验收：A10

Scenario: 编辑 123 账号时粘贴裸 JWT 被识别为 token 凭据而不是报缺字段
验收：A10

## 网页登录弹窗

网页登录弹窗的高度随内容自适应，不预留固定高度。整页截图方式下，二维码或整页画面按容器宽度等比缩放，不因网页自身留白产生上下大块空白；noVNC 方式下画面区域占满可用宽度并保持比例。底部状态区（倒计时与等待提示）紧贴内容，不出现被推到底部的大段空白。弹窗在移动端全屏展示。

Scenario: 扫码等待态弹窗没有上下大块空白，底部倒计时紧贴内容
验收：A12

验收：A12

## 登录成功文案

检测到登录态后，弹窗底部显示「当前登录用户：<昵称或账号名>」。用户名优先取后端返回的账号昵称，其次取扫码结果中的账号标识；两者都为空时显示「当前登录用户：未知」。不再显示「已检测到登录态」之类的状态说明或未翻译的英文键名。

验收：A13

Scenario: 拿不到用户名时显示「当前登录用户：未知」
验收：A13

## 凭据读取与兼容

账号列表接口保持脱敏，只返回凭据字段名与掩码；完整 Cookie 仅由超级管理员鉴权的单账号详情接口返回，前端只在账号详情与编辑弹窗中展示。Cookie/token 明文不得出现在日志、告警、错误信息与测试快照中。历史账号记录（含旧平台 id 与旧凭据格式）继续可读、可编辑、可探测；网盘分享搜索、转存、下载与失败对账行为不变。

验收：A14

Scenario: 历史账号记录在改版后仍可读取、编辑与探测
验收：A10
