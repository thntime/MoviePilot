# 目标

修复网盘下载生命周期的四类问题：下载目录与转存内容残留、后台下载失败后不换源且订阅可能被误判完成、网盘容量不足时没有告警和自动切换、以及多季/同名/续传/进度写入等正确性与性能隐患。改造后，网盘任务在成功、失败、取消和进程重启后都能被正确回收或续传；后台失败会回滚订阅的已下载事实并重新搜索其他平台资源；容量不足会在提交前被发现并切换到下一个可用平台。

# 验收示例

- A1 目录回收：move 整理成功后，网盘任务的文件与空任务目录都被回收；失败、取消或手动删除任务同样不残留空目录；copy/link 模式保留源文件与目录。
- A2 定时孤儿清理：定时任务只清理超过宽限期、且不被活动任务引用的空目录或已整理文件目录；活动任务、用户手动放置的内容和隐藏/回收站目录不受影响。
- A3 转存兜底：取链或文件大小校验失败时，已转存的云端临时目录仍会被清理；单个句柄清理失败只记录告警，不阻断其余句柄；进程重启后残留的转存目录可被定时任务发现并清理。
- A4 失败换源：网盘任务在提交成功后失败（取链失败、直链过期、容量不足、磁盘满、进程重启），订阅不会因此被标记完成；对应集数会从已下载事实中回滚，并重新搜索其他平台/站点的资源。
- A5 容量与切换：账号选择按状态、剩余容量、近期速度与主账号排序；提交前发现容量不足时发送一次告警、冷却该平台并继续尝试其他平台候选；冷却窗口内不重复告警。
- A6 正确性：多季分享按季过滤，S02E05 不会被当作 S01E05；同一任务内不同子目录的同名文件不会静默覆盖；暂停恢复时已完成且大小匹配的文件不会重下。
- A7 性能与资源：进度写入按时间/百分比节流；下载前检查本地磁盘余量并在不足时直接失败并提示；网盘任务并发数受全局上限约束；任务记录按 TTL 裁剪。
- A8 兼容性：原有网盘分享搜索、取链、下载、订阅拆包与整理行为不变；copy/link 模式不删除源文件；历史 c139 账号迁移后仍可正常下载。

# 关键决定

- copy/link 模式不删除网盘下载源文件，只回收任务记录与空目录（用户确认）。
- 允许定时清理孤儿下载目录（用户确认）；空目录宽限期 24 小时，非空且全部文件已整理的目录宽限期 7 天，清理前再次校验无活动任务引用。
- 网盘容量不足不再直接失败：提交前做容量预检，后台仍失败时由对账任务回滚并换源；两者同时保留。
- 告警阈值按“剩余容量不足以容纳本次待转存文件 × 1.2 安全系数”判断，同一账号 6 小时内只告警一次；不使用固定使用率百分比。
- 平台切换只发生在候选资源层面：分享链接与平台绑定，不能把同一链接交给另一个网盘下载。
- 账号排序优先级：状态可用 > 剩余容量足够 > 近期下载速度 EWMA > 主账号 > 账号 id。
- 订阅的已下载事实只在任务提交成功时写入；后台失败由对账任务按集回滚，不依赖用户手动清理下载历史。
- 不拆分 Supervisor：改动集中在同一条下载/整理/订阅链路，拆分会产生写域冲突，按单个 Native Change 推进。

# 约束与不变量

- 现有 JSON 任务索引格式保持向后兼容；新增字段必须有缺省值，旧记录可继续读取。
- 所有清理操作必须幂等，且不得删除活动任务正在写入的文件。
- 不记录或输出 Cookie/token 明文；告警只包含平台、账号名与容量数字。
- 定时任务必须在测试中使用临时 CONFIG_DIR，不触碰真实下载目录或数据库。
- 新增行为必须有聚焦 pytest 覆盖；不改动既有测试的断言来掩盖回归。
